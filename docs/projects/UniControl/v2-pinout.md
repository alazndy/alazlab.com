# UniControl V2 Core Pinout

## Status

This is the R2 reviewed pin matrix for the ESP32-P4-WIFI6 carrier board. It
targets the V2 Core BOM: two independently controlled Classical CAN channels,
one CAN FD channel, four relay outputs, two PWM low-side outputs, two isolated
trigger inputs, power-fail detection, a hardware watchdog/output inhibit, and the
onboard display, audio, Wi-Fi/BLE, and microSD facilities.

ADC, RTC, and one auxiliary digital input remain DNP (do not populate) options.
LIN and K-Line are no longer pin-compatible Core options: adding either without
removing a safety function requires an expansion device or a V2 variant. The
Core design does not require an I/O expander.

## Design Rules

- Every ESP32-P4 signal is 3.3 V logic. No vehicle voltage connects directly
  to a GPIO.
- GPIO7 and GPIO8 are the board I2C bus. They are shared by the onboard codec,
  the display touch interface, and any low-speed 3.3 V I2C option.
- GPIO24 and GPIO25 are USB OTG D-/D+. Do not use them for vehicle I/O.
- GPIO34 through GPIO38 are ESP32-P4 strapping pins. They are not allocated to
  the V2 carrier.
- CAN transceivers must start in standby. External pull-ups make every bus
  passive until firmware explicitly enables it.
- `OUTPUT_ARM` has an external pull-down and stays low through reset and
  self-test. `SAFETY_HB` continuously services an external window watchdog.
  Either signal becoming invalid hardware-gates every physical output OFF;
  the watchdog also resets the P4.
- `PWR_FAIL_N` is asserted by carrier hardware before `P4_5V` collapses. It is
  not generated by firmware.

## CAN Interconnects and Power Domains

### Classical CAN 1 and 2

Use one TCAN1042HGV-Q1 per bus.

| TCAN1042HGV-Q1 pin | Signal | Net |
|---:|---|---|
| 1 | TXD | Respective `CANx_TXD`; 10k pull-up to `3V3` |
| 2 | GND | `GND` |
| 3 | VCC | `CAN_5V`; 100nF local bypass |
| 4 | RXD | Respective `CANx_RXD` |
| 5 | VIO | `3V3`; 100nF local bypass |
| 6 / 7 | CANL / CANH | Connector through TVS and optional common-mode choke |
| 8 | STB | `CAN1_STB` or `CAN2_STB`; 10k pull-up to `3V3` |

Each bus gets a 120 ohm termination resistor that is fitted only when this
node is physically at a bus end. Implement it as a solder jumper or DIP switch.

### CAN FD

| MCP2518FD pin | Signal | Net / connection |
|---:|---|---|
| 1 / 2 | TXCAN / RXCAN | MCP2562FD TXD / RXD |
| 3 | CLKO/SOF | Test pad; otherwise NC |
| 4 | INT | GPIO32 (`CANFD_INT_N`) |
| 5 / 6 | OSC2 / OSC1 | 40 MHz AEC-Q200 crystal network |
| 7 | VSS | `GND` |
| 8 | INT1/GPIO1 | Test pad; otherwise NC |
| 9 | INT0/GPIO0/XSTBY | MCP2562FD STBY; external 10k pull-up |
| 10 | SCK | GPIO30 (`CANFD_SCK`) |
| 11 | SDI | GPIO29 (`CANFD_MOSI`) |
| 12 | SDO | GPIO31 (`CANFD_MISO`) |
| 13 | nCS | GPIO28 (`CANFD_CS_N`); 10k pull-up to `3V3` |
| 14 | VDD | `3V3`; 100nF local bypass plus nearby bulk capacitor |

| MCP2562FD pin | Signal | Net / connection |
|---:|---|---|
| 1 / 4 | TXD / RXD | MCP2518FD TXCAN / RXCAN |
| 2 | VSS | `GND` |
| 3 | VDD | `CAN_5V`; 100nF local bypass |
| 5 | VIO | `3V3`; 100nF local bypass |
| 6 / 7 | CANL / CANH | CAN FD connector through TVS, choke, and selectable termination |
| 8 | STBY | MCP2518FD `INT0/GPIO0/XSTBY`; 10k pull-up to `3V3` |

The corrected SPI assignment follows the ESP32-P4 native SPI2 IO_MUX:
GPIO28=CS, GPIO29=D/MOSI, GPIO30=CK, and GPIO31=Q/MISO. GPIO-matrix routing is
possible, but is deliberately avoided for the CAN FD clock path.

## Power-Fail and Output Safety Nets

| P4 signal | Hardware behavior |
|---|---|
| `PWR_FAIL_N` / GPIO20 | Open-drain early-warning output from the power supervisor; 10k pull-up to `3V3`; firmware interrupt only |
| `OUTPUT_ARM` / GPIO21 | 100k pull-down; remains low until self-test and at least one valid watchdog window complete |
| `SAFETY_HB` / GPIO22 | Heartbeat input of the external AEC-Q100 TPS3430-Q1 window watchdog; 100k pull-down defines reset state |

The watchdog's active-low fail output drives the P4 `EN` reset net. Two
AEC-Q100 quad AND gates form `SAFE_OK = PWR_FAIL_N AND WDOG_OK AND OUTPUT_ARM`
and then gate the six P4 output commands before the four relay/two PWM drivers.
Each final driver input also has a pull-down. Missing/invalid heartbeat, loss of
power-good, or reset therefore forces every physical output low without
depending on application code.

## Vehicle I/O Connections

### Isolated triggers

`ISO_TRIG1` and `ISO_TRIG2` are 9-32 V low-speed trigger inputs. The vehicle
side contains a fuse/PTC, reverse-polarity protection, TVS, current-limiting
resistor, and optocoupler LED. The board side uses a 3.3 V pull-up and presents
only the optocoupler output to GPIO26 or GPIO27.

### Relay outputs

`RELAY1_EN` through `RELAY4_EN` drive transistor or logic-level N-MOSFET relay
coil drivers. Every coil has a flyback diode. The relay contact path is separate
from logic ground and carries its own appropriately sized fuse.

### PWM low-side outputs

`PWM_OUT1` and `PWM_OUT2` drive a 3.3 V logic-level, automotive-rated N-MOSFET
through a gate resistor. Each gate has an external pull-down. The load positive
terminal is fused `VBAT`; its negative terminal is switched by the MOSFET. Add a
flyback diode or TVS at every inductive load.

## DNP Options

| Option | P4 pins | Carrier-board requirement |
|---|---|---|
| ADS1115 | Shared I2C0 GPIO7/GPIO8 | Protected four-channel analogue front end; carrier pull-ups DNP |
| RTC | Shared I2C0 GPIO7/GPIO8 | DS3231 and backup source; carrier pull-ups DNP |
| Third isolated trigger / diagnostic | GPIO23 | Same protected input circuit or test point; DNP |

The Waveshare board already fits 2.2k pull-ups on GPIO7/GPIO8. Do not populate
another strong I2C pull-up pair on the carrier. LIN, K-Line, or more than one
additional digital input require a mutually exclusive pin variant or an
expansion device; they are not silently multiplexed onto safety-critical nets.

## GPIO Budget

| Category | GPIO count |
|---|---:|
| V2 Core active | 24 |
| DNP / AUX available (`GPIO23`) | 1 |
| USB OTG reserved | 2 |
| Total exposed GPIOs | 27 |

The board exposes 27 programmable GPIOs on its 2x20 header. GPIO20-23 are
fully accounted for: GPIO20-GPIO22 provide power-fail, output-arm, and watchdog
safety; GPIO23 is the sole DNP/AUX pin; and GPIO52 independently controls CAN-2
standby. USB GPIO24/GPIO25 remain reserved. There is no untracked Core GPIO.
